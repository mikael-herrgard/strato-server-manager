## 1. System Architecture

### Overview
- **Mailcow Dockerized**: 18-container mail server stack
- **Nginx Proxy Manager (NPM)**: Reverse proxy handling SSL termination
- **Cloudflare**: DNS provider with DNSSEC enabled
- **Let's Encrypt**: SSL certificate provider

### Port Configuration
```
External (Firewall)     NPM         Mailcow
80/tcp                 → 80        → 4080 (HTTP redirect)
443/tcp                → 443       → 4433 (HTTPS)
25/tcp                              → 25 (SMTP direct)
465/tcp                             → 465 (SMTPS direct)
587/tcp                             → 587 (Submission direct)
993/tcp                             → 993 (IMAPS direct)
995/tcp                             → 995 (POP3S direct)
```

### Network Flow
```
Internet → Firewall → NPM (SSL termination) → Mailcow (HTTPS/4433)
Internet → Firewall → Mailcow (SMTP/IMAP/POP3 ports direct)
```

### 4.3 Certificate Renewal Hook

**File:** `/root/nginx/letsencrypt/renewal-hooks/deploy/sync-mailcow-certs.sh`

This script automatically:
1. Copies renewed certificates from NPM to mailcow
2. Restarts mailcow mail services
3. Updates TLSA records in Cloudflare

```bash
#!/bin/bash
# NPM Certificate Renewal Hook - Sync to Mailcow
# This script runs automatically after NPM renews certificates

set -e

# Source and destination paths
NPM_CERT="/root/nginx/letsencrypt/live/npm-2/fullchain.pem"
NPM_KEY="/root/nginx/letsencrypt/live/npm-2/privkey.pem"
MAILCOW_CERT="/opt/mailcow-dockerized/data/assets/ssl/cert.pem"
MAILCOW_KEY="/opt/mailcow-dockerized/data/assets/ssl/key.pem"

# Log file
LOG_FILE="/var/log/mailcow-cert-sync.log"

echo "[$(date)] Starting certificate sync..." | tee -a "$LOG_FILE"

# Check if NPM certificates exist
if [ ! -f "$NPM_CERT" ] || [ ! -f "$NPM_KEY" ]; then
    echo "[$(date)] ERROR: NPM certificates not found!" | tee -a "$LOG_FILE"
    exit 1
fi

# Backup current mailcow certificates
cp "$MAILCOW_CERT" "${MAILCOW_CERT}.bak-$(date +%Y%m%d-%H%M%S)" 2>/dev/null || true
cp "$MAILCOW_KEY" "${MAILCOW_KEY}.bak-$(date +%Y%m%d-%H%M%S)" 2>/dev/null || true

# Copy new certificates
cp "$NPM_CERT" "$MAILCOW_CERT"
cp "$NPM_KEY" "$MAILCOW_KEY"

echo "[$(date)] Certificates copied successfully" | tee -a "$LOG_FILE"

# Restart mailcow services that use SSL
cd /opt/mailcow-dockerized
docker restart mailcowdockerized-dovecot-mailcow-1 \
               mailcowdockerized-postfix-mailcow-1 \
               mailcowdockerized-nginx-mailcow-1

echo "[$(date)] Mailcow services restarted" | tee -a "$LOG_FILE"

# Wait for services to fully restart
sleep 5

# Update TLSA records in Cloudflare
echo "[$(date)] Updating TLSA records in Cloudflare..." | tee -a "$LOG_FILE"
if [ -f "/opt/mailcow-dockerized/update-tlsa-cloudflare.sh" ]; then
    if /opt/mailcow-dockerized/update-tlsa-cloudflare.sh; then
        echo "[$(date)] TLSA records updated successfully!" | tee -a "$LOG_FILE"
    else
        echo "[$(date)] WARNING: TLSA update failed! Check /var/log/tlsa-update.log" | tee -a "$LOG_FILE"
        echo "[$(date)] You may need to update TLSA records manually" | tee -a "$LOG_FILE"
    fi
else
    echo "[$(date)] WARNING: TLSA update script not found at /opt/mailcow-dockerized/update-tlsa-cloudflare.sh" | tee -a "$LOG_FILE"
    echo "[$(date)] Please update TLSA records manually" | tee -a "$LOG_FILE"
fi

echo "[$(date)] Certificate sync completed successfully!" | tee -a "$LOG_FILE"
```

**Make executable:**
```bash
chmod +x /root/nginx/letsencrypt/renewal-hooks/deploy/sync-mailcow-certs.sh
```

### 5.2 Proxy Host Configuration

**Critical Settings for All Proxy Hosts:**

6. **Force SSL:** ✅ Enabled
7. **HTTP/2 Support:** ✅ Enabled
8. **HSTS Enabled:** ✅ Enabled

**Custom Nginx Configuration (Advanced tab) for all Mailcow proxy hosts:**
```nginx
# Strip Mailcow's headers and set correct ones
proxy_hide_header Strict-Transport-Security;
proxy_hide_header Referrer-Policy;

add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;
more_set_headers "Referrer-Policy: same-origin";
more_set_headers "Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; frame-ancestors 'self'; form-action 'self'; base-uri 'self';";
```

**Why these headers are needed:**
- Mailcow's nginx sends `Strict-Transport-Security: max-age=15768000` (6 months) and
  `Referrer-Policy: strict-origin` — both fail internet.nl tests
- `proxy_hide_header` strips Mailcow's headers; the replacement headers are set by NPM
- `more_set_headers` (from headers-more module) is used for CSP and Referrer-Policy
  because nginx's `add_header` in server context is overridden by NPM's location block
- CSP requires `unsafe-inline`/`unsafe-eval` because Mailcow's SOGo/admin UI needs them

## 6. Automated TLSA Record Updates

DANE/TLSA records must match the certificate fingerprint. This script automates updates via Cloudflare API.

### 6.1 Cloudflare API Credentials

**Required Information:**
1. **API Token:** Cloudflare API token with DNS Edit permissions
2. **Zone ID:** Your Cloudflare zone ID for villaherrgard.com

**Get Zone ID:**
```bash
# Method 1: Via Cloudflare Dashboard
# Go to: Cloudflare Dashboard → Select domain → Overview (right sidebar)

# Method 2: Via API
curl -s -X GET "https://api.cloudflare.com/client/v4/zones?name=villaherrgard.com" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" | jq -r '.result[0].id'
```

### 6.2 TLSA Update Script

**File:** `/opt/mailcow-dockerized/update-tlsa-cloudflare.sh`

```bash
#!/bin/bash
##############################################################################
# Automated TLSA Record Updater for Cloudflare
#
# This script automatically updates DANE/TLSA records in Cloudflare DNS
# when SSL certificates are renewed. It extracts the certificate fingerprint
# from the mail server and updates records for ports 25, 465, and 587.
#
# Requirements:
# - Cloudflare API Token with DNS Edit permissions
# - Cloudflare Zone ID for your domain
# - openssl, curl, jq installed
##############################################################################

set -e

# ============================================================================
# CONFIGURATION - MUST BE FILLED IN
# ============================================================================
DOMAIN="villaherrgard.com"
MAIL_SERVER="mail.villaherrgard.com"
CF_API_TOKEN="YOUR_CLOUDFLARE_API_TOKEN"  # <-- ADD YOUR TOKEN HERE
CF_ZONE_ID="YOUR_CLOUDFLARE_ZONE_ID"      # <-- ADD YOUR ZONE ID HERE

# Certificate and logging
CERT_FILE="/opt/mailcow-dockerized/data/assets/ssl/cert.pem"
LOG_FILE="/var/log/tlsa-update.log"

# Ports to update TLSA records for
PORTS=(25 465 587)

# ANSI color codes for output
GREEN='\033[0;32m'
RED='\033[0;31m'
YELLOW='\033[1;33m'
NC='\033[0m' # No Color

# ============================================================================
# FUNCTIONS
# ============================================================================

log() {
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] $1" | tee -a "$LOG_FILE"
}

error() {
    echo -e "${RED}[ERROR]${NC} $1" | tee -a "$LOG_FILE"
}

success() {
    echo -e "${GREEN}[SUCCESS]${NC} $1" | tee -a "$LOG_FILE"
}

warning() {
    echo -e "${YELLOW}[WARNING]${NC} $1" | tee -a "$LOG_FILE"
}

# ============================================================================
# VALIDATION
# ============================================================================

log "Starting TLSA record update process..."

# Check if required tools are installed
for tool in openssl curl jq; do
    if ! command -v $tool &> /dev/null; then
        error "$tool is not installed. Please install it first."
        exit 1
    fi
done

# Check if API credentials are configured
if [ "$CF_API_TOKEN" = "YOUR_CLOUDFLARE_API_TOKEN" ] || [ "$CF_ZONE_ID" = "YOUR_CLOUDFLARE_ZONE_ID" ]; then
    error "Cloudflare API credentials not configured!"
    error "Please edit this script and add your CF_API_TOKEN and CF_ZONE_ID"
    exit 1
fi

# ============================================================================
# GET CERTIFICATE FINGERPRINT
# ============================================================================

log "Getting current certificate fingerprint from ${MAIL_SERVER}:25..."

# Try to get fingerprint from running mail server
FINGERPRINT=$(echo | openssl s_client -connect ${MAIL_SERVER}:25 -starttls smtp 2>/dev/null | \
              openssl x509 -noout -pubkey 2>/dev/null | \
              openssl pkey -pubin -outform DER 2>/dev/null | \
              openssl dgst -sha256 -binary | \
              xxd -p -c 64)

# Fallback: try to get from certificate file
if [ -z "$FINGERPRINT" ] && [ -f "$CERT_FILE" ]; then
    warning "Could not get fingerprint from server, trying certificate file..."
    FINGERPRINT=$(openssl x509 -in "$CERT_FILE" -noout -pubkey | \
                  openssl pkey -pubin -outform DER | \
                  openssl dgst -sha256 -binary | \
                  xxd -p -c 64)
fi

# Validate fingerprint
if [ -z "$FINGERPRINT" ]; then
    error "Failed to extract certificate fingerprint!"
    exit 1
fi

log "Certificate fingerprint: $FINGERPRINT"

# ============================================================================
# UPDATE TLSA RECORDS FOR EACH PORT
# ============================================================================

UPDATED_PORTS=()
FAILED_PORTS=()

for PORT in "${PORTS[@]}"; do
    RECORD_NAME="_${PORT}._tcp.${MAIL_SERVER}"
    log "Processing TLSA record for port $PORT (${RECORD_NAME})..."

    # TLSA record format: "3 1 1 <fingerprint>"
    # 3 = DANE-EE (Domain Issued Certificate)
    # 1 = SPKI (Subject Public Key Info)
    # 1 = SHA-256 hash
    TLSA_DATA="3 1 1 ${FINGERPRINT}"

    # Check if TLSA record already exists
    EXISTING_RECORD=$(curl -s -X GET \
        "https://api.cloudflare.com/client/v4/zones/${CF_ZONE_ID}/dns_records?type=TLSA&name=${RECORD_NAME}" \
        -H "Authorization: Bearer ${CF_API_TOKEN}" \
        -H "Content-Type: application/json")

    RECORD_ID=$(echo "$EXISTING_RECORD" | jq -r '.result[0].id // empty')
    CURRENT_FINGERPRINT=$(echo "$EXISTING_RECORD" | jq -r '.result[0].data.certificate // empty')

    if [ -n "$RECORD_ID" ]; then
        # Record exists - check if update is needed
        if [ "$CURRENT_FINGERPRINT" = "$FINGERPRINT" ]; then
            success "TLSA record for port $PORT already up to date"
            UPDATED_PORTS+=($PORT)
            continue
        fi

        log "Updating TLSA record for port $PORT (ID: $RECORD_ID)..."

        # Update existing record
        RESPONSE=$(curl -s -X PUT \
            "https://api.cloudflare.com/client/v4/zones/${CF_ZONE_ID}/dns_records/${RECORD_ID}" \
            -H "Authorization: Bearer ${CF_API_TOKEN}" \
            -H "Content-Type: application/json" \
            --data "{
                \"type\": \"TLSA\",
                \"name\": \"${RECORD_NAME}\",
                \"data\": {
                    \"usage\": 3,
                    \"selector\": 1,
                    \"matching_type\": 1,
                    \"certificate\": \"${FINGERPRINT}\"
                },
                \"ttl\": 3600
            }")
    else
        # Record doesn't exist - create new
        log "Creating new TLSA record for port $PORT..."

        RESPONSE=$(curl -s -X POST \
            "https://api.cloudflare.com/client/v4/zones/${CF_ZONE_ID}/dns_records" \
            -H "Authorization: Bearer ${CF_API_TOKEN}" \
            -H "Content-Type: application/json" \
            --data "{
                \"type\": \"TLSA\",
                \"name\": \"${RECORD_NAME}\",
                \"data\": {
                    \"usage\": 3,
                    \"selector\": 1,
                    \"matching_type\": 1,
                    \"certificate\": \"${FINGERPRINT}\"
                },
                \"ttl\": 3600
            }")
    fi

    # Check if API call was successful
    API_SUCCESS=$(echo "$RESPONSE" | jq -r '.success')

    if [ "$API_SUCCESS" = "true" ]; then
        success "Updated TLSA record for port $PORT"
        UPDATED_PORTS+=($PORT)
    else
        ERROR_MSG=$(echo "$RESPONSE" | jq -r '.errors[0].message // "Unknown error"')
        error "Failed to update TLSA record for port $PORT: $ERROR_MSG"
        FAILED_PORTS+=($PORT)
    fi
done

# ============================================================================
# SUMMARY
# ============================================================================

log "========================================="
if [ ${#FAILED_PORTS[@]} -eq 0 ]; then
    success "TLSA records update completed!"
    log "Certificate fingerprint: $FINGERPRINT"
    log "Updated ports: ${UPDATED_PORTS[*]}"
    log "========================================="
    exit 0
else
    error "TLSA records update completed with errors!"
    log "Certificate fingerprint: $FINGERPRINT"
    log "Updated ports: ${UPDATED_PORTS[*]}"
    log "Failed ports: ${FAILED_PORTS[*]}"
    log "========================================="
    exit 1
fi
```

## 8. CAA Records

CAA (Certificate Authority Authorization) records specify which CAs can issue certificates for your domain.

### 8.1 DNS Configuration

```dns
villaherrgard.com    CAA    0 issue "letsencrypt.org"
villaherrgard.com    CAA    0 issuewild "letsencrypt.org"
villaherrgard.com    CAA    0 issuemail ";"
villaherrgard.com    CAA    0 iodef "mailto:postmaster@villaherrgard.com"
```

**Explanation:**
- `issue`: Authorizes Let's Encrypt for standard certificates
- `issuewild`: Authorizes Let's Encrypt for wildcard certificates
- `issuemail`: Prevents S/MIME certificate issuance (`;` = no CA authorized)
- `iodef`: Email for CAA violation reports

### 8.2 Cloudflare Additions

Cloudflare automatically adds their CAs when you create CAA records:
- `digicert.com`
- `pki.goog`
- `ssl.com`
- `comodoca.com`

This is normal and allows Cloudflare services to function.

### 8.3 Verification

```bash
dig CAA villaherrgard.com +short
```

## 12. Troubleshooting

### 12.1 Certificate Issues

**Problem:** Mailcow services fail after certificate renewal

**Solution:**
```bash
# Check certificate validity
openssl x509 -in /opt/mailcow-dockerized/data/assets/ssl/cert.pem -noout -dates -subject

/root/nginx/letsencrypt/renewal-hooks/deploy/sync-mailcow-certs.sh

# Check logs
tail -50 /var/log/mailcow-cert-sync.log

# Restart mailcow services
cd /opt/mailcow-dockerized
docker restart mailcowdockerized-dovecot-mailcow-1 \
               mailcowdockerized-postfix-mailcow-1 \
               mailcowdockerized-nginx-mailcow-1
```

### 12.2 TLSA Record Mismatch

**Problem:** DANE validation fails, certificate doesn't match TLSA records

**Solution:**
```bash
# Get current certificate fingerprint
echo | openssl s_client -connect mail.villaherrgard.com:25 -starttls smtp 2>/dev/null | \
    openssl x509 -noout -pubkey | \
    openssl pkey -pubin -outform DER | \
    openssl dgst -sha256 -binary | \
    xxd -p -c 64

# Get TLSA record fingerprint
dig +short TLSA _25._tcp.mail.villaherrgard.com | awk '{print $4}'

# If they don't match, update TLSA records
/opt/mailcow-dockerized/update-tlsa-cloudflare.sh

# Check logs
tail -50 /var/log/tlsa-update.log

# Wait for DNS propagation (5-15 minutes)
# Verify with: https://dane.sys4.de/
```

### 12.3 DNS Issues

**Problem:** DNS records not resolving or propagating

**Solution:**
```bash
# Check from multiple DNS servers
dig @8.8.8.8 mail.villaherrgard.com +short
dig @1.1.1.1 mail.villaherrgard.com +short

# Check DNSSEC
dig +dnssec villaherrgard.com | grep -E "ad|RRSIG"

# Flush local DNS cache
systemd-resolve --flush-caches  # Ubuntu/Debian
```

**Problem:** TLSA records showing old fingerprint

**Solution:**
- Wait 1-24 hours for caching resolvers to update
- TLSA records have longer cache times
- Test with authoritative nameservers: `dig @ns1.cloudflare.com TLSA _25._tcp.mail.villaherrgard.com`
